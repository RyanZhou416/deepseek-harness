# Agent Note: 保留结算、渲染失败和过程折叠中的回复

Status: implemented

[English](2026-10-15-session-reply-visibility.md) | 中文

## 问题

持久助手回复可能因延迟提交倒序追加、单个渲染错误停用共享助手注册项，或最后可用回复被归为可折叠过程内容，而不出现在 Chat 中。避免这些故障时，必须保留准备态工具身份、自定义渲染器递补、思考内容展开规则和页脚操作资格。

## 决策

### 提交与清理分别拥有各自职责

[客户端事件源](../../../../packages/api/session-controller/src/client/contract/events.ts)根据包含临时条目的已发布高水位选择 `commitAssistant` 路径。更晚的序号使用普通追加；更早的提交使用 `insert-assistant` 和有序 Context 重放。既有快照保持不可变，同一事件的重复提交为空操作，冲突占位被拒绝。普通追加仍要求序号递增。

[尝试状态归并](../../../../packages/api/session-controller/src/client/sessions/assistant-stream.ts)将成功尝试的临时行保留到首个所属步骤或轮次结束。如果该边界已经到达，就原子完成提交与清理。这保留了[工具三阶段准备态](../architecture/2026-09-22-tool-call-three-phases.zh.md)：持久助手消息不是未调度工具行的替代来源。失败、中断和放弃尝试保留立即清理规则。

[Chat](../../../../packages/client/ui-chat/src/client/conversation-nodes/assistant.ts) 与 [Trajectory](../../../../packages/client/ui-trajectory/src/client/trajectory-assistant-definition.ts)在已初始化和部分窗口归并中，都保持已结算消息状态对后到临时分片的权威性。重试和边界仍更新各自状态；工具 Definition 保留原始匹配直到清理。不改变会话 schema、持久化代次、SDK 协议或后端执行策略。

### 注册项显式选择实例隔离

keyed 注册项可以设置 `failureScope: 'occurrence'`，由拥有方提供 `occurrenceRecovery: { fallback, resetKey }`。只有内置助手注册项选择该行为。渲染器上报局部错误而不停用注册项，因此其他实例仍然可用。未选择新策略的覆盖项保留原有停用及较低优先级递补行为。缺少恢复数据和 `SlotAssemblyError` 仍是装配错误，不是可恢复消息错误。

[Chat 降级内容](../../../../packages/client/ui-chat/src/client/chat/AssistantRecovery.tsx)直接显示当前文本，并提示不可用的非文本内容。它不调用 Markdown、文件解析器、图片渲染或原始载荷显示。思考实例只显示提示。带类型标记的消息代次与 Session 实例代次重置失败实例；普通流式更新只刷新其纯文本。健康实例不会因恢复键变化重新挂载。降级内容自身失败时进入父级监督，不递归调用自己。

Chat 还为每个作用域内的回复代次选择一次 DOM `NotFoundError` 自动重新挂载，先将受损子树卸载为降级内容。这覆盖翻译扩展在 React 更新前移动节点的情况，包括正常代次重置已经发生后的结算时失败。实时和已完成回复都允许翻译；整个生成阶段禁止翻译，会让依赖翻译的用户无法及时阅读长回复。Markdown 渲染器保护文本更新，不等待结算。重试限制在局部且次数有界，不逐 token、不定时执行，也不全局修改 DOM 方法。

### 已关闭轮次保护最后可用回复

[轮次过程 Definition](../../../../packages/client/ui-chat/src/client/conversation-nodes/turn-process.ts)在已关闭轮次中选择最新已加载、有可见内容的已结算回复，包括伴随工具调用的正文或纯工具步骤之前的正文。开放轮次保留末步骤规则。选择缓存在结算、重试、边界、重放和步骤首个携带回复内容的实时帧到达时失效。缓存的合成中断记录从选中步骤刷新，不进行整轮扫描。

回复实例依据轮次、步骤身份和内容部分受到保护，而不是依据临时排序锚点。思考内容和回复前后的过程共用可用的外层展开控件。被替换节点保持隐藏。页脚文本操作、导航预览、文件提及所有权和用量仍采用独立策略；显示更早的回复不会启用针对非末尾消息的 fork 操作。

## 考虑过的替代方案

**只比较持久游标，或清理每个延迟成功尝试。** 持久游标不变时，临时条目可能已经高于暂存结算。更晚的工具调用不是关闭边界；提前清理会丢掉其他准备行。

**每次追加都排序、重建整个窗口，或忽略顺序断言。** 这些做法掩盖生产方错误并增加流式成本。有序插入是显式操作，只重放受影响 Context。

**全局禁用停用机制，或只让拥有方决定它。** 两者都会改变自定义渲染器递补。注册项选择实例隔离，拥有方提供恢复内容。

**保护所有中间回复，或统一折叠、页脚与导航选择。** 这些做法扩大显示行为变化或改变操作资格。只有最后可用回复获得整轮保护，其他选择器保留各自约定。

## 结果与影响

客户端保留现有流与结束帧关联，因此结束帧永久缺失时，仍需现有跟随恢复或重新打开。实例隔离对显式选择的注册项放弃较低优先级递补，纯文本也不能重现富媒体。同一步骤重试期间仍可读取降级文本，直到新结算代次重试富文本渲染。

## 验证

源码回归覆盖延迟边界与分片、不可变窗口插入、重复与空操作处理、工具准备态、Chat/Trajectory 已结算状态、多渲染实例、覆盖项递补、Session 代次恢复、字面值降级文本，以及已关闭轮次的选择和展开。工作量断言覆盖实时与延迟帧的选择；恢复旧实现后，对应回归对照会失败。

[录制 Web 场景](../../../../apps/web/tests/turn-tail-actions.e2e.ts)验证末步骤无正文时，更早的回复仍可见、工具可访问、分支操作不可用，且刷新后保持一致。其工具行定位器同时接受已调度工具和平台上的工具不可用结果。独立 Chromium 探针还针对构建后的前端验证了原生 PowerShell 成功、注入消息渲染失败和延迟结束帧投递，未修改真实会话数据或已部署包。
