# v0.1.24-dsh023a2.1 — Harness 0.2.3-alpha.2 compatibility

Prerelease channel: npm `dsh023a2`. Recommended host stays Harness `0.2.2-rc.1`; `0.2.3-alpha.2` is a preview target.

- Create members against the flattened `SubagentActivationSpec` and, where the host publishes it, through the AgentTeams member entry (`dsh.subagent.startAgentTeamsMember`) so a user's global subagent model override never rewrites a member route. Hosts through `0.2.2-rc.1` keep their nested request and stay supported.
- Stop selected members without the tree-wide `drainDescendants` cutoff: hosts that lost the targeted drain cancel and interrupt exactly those children, and the per-step admission check plus the retired-id delivery guard keep them from working again.
- Use the host's `admit()` route decision (the 0.2.3 replacement for `requestRejection`), read lineage from Session headers (the agent registry no longer tracks runtime owners), and drop the removed `subagents.list()` call from the missing-provider diagnostic.
- Pin the development host cohort to `0.2.3-alpha.2`, Cordis `4.2.0-alpha.1`, and Schemastery `3.20.0-alpha.1`.

`0.2.3-alpha.2` requires the host build that restores `packages/subagent/subagent/src/internal.ts` (the host prompt protocol and the AgentTeams member entry); a vanilla upstream `0.2.3-alpha.2` host has neither and the plugin fails loud at mount rather than degrading member delivery.

Validation scope and limitations: [migration record](../docs/harness-0.2.3-alpha.2/README.md).

Install the published version with `dsh plugin --profile web add --save-exact @nanmicoder/dsh-agent-teams@0.1.24-dsh023a2.1`. This prerelease does not move npm `latest`.
