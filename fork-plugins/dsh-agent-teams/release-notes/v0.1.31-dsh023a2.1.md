# v0.1.31-dsh023a2.1

Fork build of upstream [`v0.1.31`](https://github.com/NanmiCoder/dsh-agent-teams/releases/tag/v0.1.31) for DeepSeek Harness `0.2.3-alpha.2`. Release channel: npm `dsh023a2` (prerelease; never `latest`). The package remains private to this fork; the public npm package is built from upstream, not from this tree.

## Upstream changes carried by this release

- Member delivery now joins the audited 0.2.2-rc.2+ tree manager (`rootOf`, `manager.deliverToMember`, `manager.dispose`) and creates members with the flat activation spec on that host generation; targeted stops join only the selected creation branches instead of using the host's tree-wide drain.
- A member that parks an open attempt notifies the captain once, and a guidance turn preserves the parked attempt, so a status poll cannot deliver the same task twice.
- Inline team plans keep the member execution prompts they were created with; a refused edit on a running plan names the tasks and member tools still available.
- Blank task subjects are rejected before writing state, each status flag is shown once, and member tasks settle after a terminal output limit.
- Workspace audits run off the host event loop, activity polls are scoped and revalidated, and session history is read in ranged batches instead of copying whole logs.
- The compatibility policy moves from an enumerated peer list to a minimum host requirement, and a `check:upstream` report compares the published host and plugin channels.

## Fork changes kept

- **0.2.3-alpha.2 host adapters.** Member creation prefers the host's `Symbol.for('dsh.subagent.startAgentTeamsMember')` entry, which is the only creation path that does not apply the user's global subagent model override. The plugin's own member route stays a user-declared exception, and a host without the entry still goes through `startActivation`.
- **Raw Web route admission.** 0.2.3-alpha.2 authorizes registered routes itself, so the panel routes declare `auth: 'required'`. Hosts through 0.2.2 keep the plugin's own `requestRejection` gate and its `401`/`403`/`503` JSON. The plugin never calls `Connection.admit()` from its own fiber, because Cordis resolves that method's `connection.authentication` read through the calling fiber and throws there.
- **PTC program format.** Capability tests and the protocol fixture emit programs for `ctx.ptcRuntime.programFormat`; product code does not parse program text.
- **Cold-captain recovery.** A recorded captain is attached through the Session Controller's `resolveAgent` (or `ctx.agents.resume` on older hosts), and an id mismatch is rejected instead of fabricating a resident captain.
- **Unread mailbox projection.** `readUnreadMailbox()` keeps its pending-only 256-entry / 8 MiB bounded LRU with file-replacement detection, per-call lease and exact mutation invalidation; the disk JSONL format is unchanged.
- **Crash-durable state.** `atomicWriteText()` fsyncs the temp file before the atomic rename and the direct-overwrite fallback; workspace scans skip content-damaged teams with one `DSH_AGENT_TEAMS_UNREADABLE_TEAM` warning while direct team reads still throw.
- **Task-first scheduling and dispatch recovery.** A ready task is claimed before unread mail, every dispatch failure leaves a readable `spawnError`, and a dead activation is retired and replaced by one fresh activation for the same member and attempt instead of rolling the task back to pending.
- **Scoped activity reads.** The state route still accepts the fork's `captainSessionId`, paired `teamCaptainSessionId`+`teamId` targets and `detail=1` scope, rejects malformed scope with `400`, and keeps full legacy payloads for unscoped callers. It additionally accepts the upstream client's `session=` and `summary=1` switches and revalidates unchanged polls with an ETag.
- **Targeted member stops.** Stopping members disposes only the selected tree branches; legacy hosts keep their targeted drain, and a host without either primitive cancels and interrupts exactly the selected children.

## Retired fork behaviors

- Fork-owned member model selection (`installModelSelection` ref, saved-route recording and in-place fallback retry) is now upstream's Agent-owned selection: the fallback route is recorded on `Agent.model` and the member continues in a new turn. The fork helpers were removed.
- `drainMemberChildren(ctx, …)` keeps the fork signature but the implementation for tree hosts is upstream's branch-owned disposal; the earlier cancel+interrupt path remains only as the fallback for a host with neither a targeted drain nor the tree manager.
- The fork's `collectTeamsActivity(captainSessionId, summary)` selection was folded into one options object that serves both the fork scope parameters and the upstream `summary` trim. `includeDetails` remains as a fork alias.
