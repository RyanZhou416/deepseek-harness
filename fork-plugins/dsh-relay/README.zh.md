# dsh-relay

[English](README.md) | 中文

把本机 DSH Web 通过 DshRelay 中继服务器发布到个人地址 `https://<用户名>.<服务器域名>/`，并提供内置设置页。插件用管理员签发的账号和个人客户端密钥登录，每次连接都向中继上报一枚新铸造的 DSH 浏览器会话 Cookie，并托管一条指向本机 DSH Web 端口的 `frpc` 隧道。

插件不包含任何部署值。中继域名、用户名、密码和客户端密钥均由用户填写并保存在 DSH 凭据服务中，绝不写入 `cordis.yml` 或 profile patch。

## 安装

Windows 上仓库的 `build.cmd` 会构建所有 fork 插件并链接进选定的 `web` profile：

```powershell
.\build.cmd
```

开发时只构建本插件：

```powershell
cd fork-plugins\dsh-relay
..\..\node_modules\.bin\tsdown
```

然后在仓库根运行 `scripts/fork-plugins-build.ts`；它从源码构建 `lib/index.js`（宿主）与 `lib/client.js`（浏览器），并以 pnpm `link:` 安装暂存目录。插件要求 DSH `0.2.2-rc.1`、Cordis `4.1.0` 与 `@deepseek-ai/schemastery` `3.19.0`。

宿主半需要 `credentials`、`connection` 与 `webServer` 服务。无头组合仍可加载本插件，但不提供隧道。浏览器半在设置的 **远程访问** 页面注册一个设置节。

## 设置

设置 → **远程访问** 提供四个字段：

- **服务器域名** —— 中继的基础域名（例如承载用户子域名的域名）。只接受 `https`；通常直接填写裸域名。
- **用户名** —— 账号的子域名标签：小写字母、数字和连字符，遵循中继协议。
- **密码** —— 账号密码。已保存时显示 **已保存** 占位；留空表示不修改。
- **客户端密钥** —— 管理员签发的个人 `dshk_…` 密钥。同样显示 **已保存**，留空表示不修改。

当两个字段能组成有效地址时，页面立即显示 `https://<用户名>.<域名>/`。**保存** 写入字段；**连接**/**断开** 启停隧道；**修改密码** 要求当前密码并两次输入新密码。**DSH 启动时自动连接** 开关保存在同一条凭据记录中。

状态区显示 **未配置**、**正在下载 frpc**、**正在连接**、**已连接**（含远端端口和上次成功时间）或 **失败**，并把中继协议错误码映射为可读原因，例如密钥无效、密码错误、用户名不合法、端口池耗尽或服务器不可达。

## 工作原理

1. 校验已保存字段，并从 `ctx.webServer.port` 读取本机 DSH Web 监听端口。
2. 用 DSH connection 插件存放在凭据记录 `client-connection/browser-session` 中的签名密钥，为 `127.0.0.1:<端口>` 铸造 DSH 浏览器会话 Cookie。有效期等于宿主配置的 `cookieMaxAgeDays` 减一天，最少一天。
3. 携带用户名、密码、authority 与 Cookie，以个人客户端密钥鉴权，`POST https://<域名>/__dsh/api/v1/connect`。
4. 按中继返回的 frp 版本下载官方 release，校验 SHA-256 后解压 `frpc`，并把配置、共享令牌和 CA 证书写入 `<DSH_HOME>/dsh-relay/run/`。
5. 用该配置启动 `frpc`；收到 `login to server success` 与 `start proxy success` 视为已连接；异常退出按指数退避重启。

每次连接都会重新铸造 Cookie；保持连接期间，插件每隔 `cookieRefreshIntervalMs`（默认 12 小时）再登记一次，因此无论 DSH 连续运行多久，中继保存的绑定都落在宿主的 Cookie 有效期之内。刷新失败时隧道保持运行，下一个周期重试；中继返回的隧道参数变化时，插件完整重连。

## 安全边界

- 密码与客户端密钥保存在 DSH 凭据服务中，不写入 `cordis.yml`、profile patch、错误信息或日志；RPC 状态只返回“是否已保存”。
- 本地 run 目录仅当前用户可访问（`0700`），每个生成文件以独占方式写入并仅当前用户可读（`0600`）。
- 中继 API 只接受 `https` 服务器域名。frp 压缩包在解压前校验固定 SHA-256，未知版本直接拒绝而不是运行。
- 设置 RPC 位于 connection 插件已鉴权的 `/api` 通道之下（`/api/relay.*`），继承 Host/Origin 栅栏和浏览器会话校验。
- `frpc` 以清理过的环境运行：名称含 `KEY`、`SECRET`、`TOKEN` 或 `PASSWORD` 的变量会被移除。

## 故障排查

- **DSH 浏览器会话密钥不可用** —— 宿主尚未创建会话签名密钥。先打开一次 DSH 网页，再重试。
- **客户端密钥无效或已被吊销** —— 向中继管理员索取新密钥；已吊销的密钥会拒绝之后的所有请求。
- **客户端密钥已绑定其他用户名** —— 该密钥已绑定到别的账号，请使用为此用户名签发的密钥。
- **中继使用的 frp 版本没有已固定的下载校验值** —— 中继管理员更换了 frp release 而未更新客户端，或 `frpcHashes` 需要增加该版本。部署方也可用 `frpcPath` 指向已有的 `frpc` 可执行文件。
- **下载的 frpc 压缩包 SHA-256 校验失败** —— 下载损坏或被替换；请重试，并在中继更换 release 时核对固定哈希。
- **frpc 无法启动隧道** —— run 目录保留着上次生成的配置与令牌文件供排查。不要外传：其中包含隧道凭据。
- **隧道进程比宿主存活更久** —— 断开或卸载时插件会停止并等待 `frpc` 退出。若宿主被强杀，请手动结束残留的 `frpc` 进程。

## 已知限制

- 插件依据文档化的客户端 API 开发；本仓库尚未验证与已部署中继的实机互操作。
- frp 压缩包固定为 `0.71.0` 的 `win32`、`darwin`、`linux` 的 `x64` 与 `arm64`。其他 release 需要在 `frpcHashes` 中固定哈希；未固定的版本会被拒绝。
- 若中继实际提供的 frp release 与管理员告知的不同，客户端在固定该 release 之前无法连接。
