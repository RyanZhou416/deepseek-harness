# AetherShell plugin maintenance

## Behavior

This optional bundle exposes native operation discovery, positional JSON calls, structured pipelines, and AetherShell expression evaluation alongside the existing shell tools. It also adds owner-scoped persistent interpreter sessions while the live-agent registry is mounted, and one background-job starter while the job registry is mounted. It does not register or replace `ctx.shell`. Every interpreter process runs under the Host's subprocess provider and the calling Session's DSH file policy; the external AetherShell interpreter is not an authority for that policy. Sessions and background jobs introduce no Session format change and keep no code checkpoint: a session is one long-lived `ae agent interactive` process whose native variables, functions, current directory and environment live only in that process — isolated from other handles while the real host filesystem stays shared — and a job is one fresh interpreter process per program.

## Preservation rule

Keep query interpreter processes stateless while retained result snapshots remain owned by the exact calling Agent. Keep the result-page and session surfaces conditional on the live-agent registry and the job surface conditional on its registry, so a composition without `agents` or `jobs` never advertises a handle no controller can serve. Keep the session read a consuming drain of output written between calls, refused while a call is in flight, so output is delivered exactly once and never silently discarded. Preserve PowerShell and Bash bindings, and never silently retry a denied operation through another shell. Clear inherited AetherShell control variables before applying deployment settings. Keep `legacy` as the default structured-data mode, with its interpolation, record-key and null-seed guards. `typed-v1` may forward those data forms only after a per-call capability probe confirms protocol version 1 and all typed argument, pipeline-input and explicit-null features. Probe and request share the call deadline and DSH file policy; failure stops before user data is sent, with no fallback or version-label inference. Keep exact-number checks in both modes. A session program keeps the caller's own interpolation by reaching the interpreter as an encoded string literal inside the native session call, while a background job program travels the command line exactly as `aether_eval` does, with no wrapper introduced; preserve that distinction when either channel changes. Keep the ownership rules: a session belongs to the exact live Agent that opened it, is refused to every other agent, is closed rather than reused when the caller's file policy changed, and is terminated when a deadline or cancellation stops an in-flight command because no state can be safely resumed. Keep a background job owned by the registry until it settles, keep `job_kill` a request whose settlement follows managed-process cleanup, and keep job output the raw structured-by-nothing streams rather than a decoded result document. Preserve explicit interpreter, response, cancellation, confinement and cleanup-failure reporting rather than treating process exit zero as a successful native call.

## Foreground query handoff

Call, pipeline and eval queries register one `aether` job before capability checks or execution when a live owner, job registry and `promoteOnTimeout` are available. An explicit admission gate releases work only after registration and initial wait attachment. `timeoutMs` bounds the foreground wait; expiry returns the same job id without kill, replay or output consumption. `executionTimeoutMs` separately limits the entire typed probe/request sequence; probes remain bounded even when execution is unlimited. Native `proc_run` deadlines are never rewritten. Discovery, persistent sessions and the raw-stream background starter keep their existing behavior.

Finalize each canonical query outcome once, through the existing complete-result bound and retention. Inline completion removes the unseen job; promotion leaves its final JSON outcome for one terminal `job_output` read. Do not give query jobs a second cap equal to the canonical content budget: generic status wrappers must not tail-cut a complete JSON result or its retrieval id. These query jobs do not expose protocol stdout fragments as streaming progress. Raw `aether_job_start` remains the stream-oriented interface.

Explicit tool cancellation before handoff cancels and joins the same producer; it is not wait expiry. After handoff the call's signal no longer owns the job. Owner disposal, plugin disposal, job kill and hard execution limits still terminate through the existing DSH subprocess service. Refused admission may fall back to one hard-deadline foreground run only before a producer was invoked; no post-start failure can cause a second execution. Missing job ownership or disabled promotion uses the smaller positive foreground/runtime deadline. The [upgrade guide](../../docs/upgrade-guide/v0.2.1-rc.2/aether-foreground-handoff/guide.md) owns caller migration.

## Retained results

Successful call, pipeline and eval values that exceed the complete inline budget may return a distinct retained-result outcome. Keep the complete fidelity-checked JSON value in bounded plugin memory; never retain a truncated stream, silently evict a live result to admit another, write a native cache, or re-run an operation while paging. Enforce per-Agent handle and byte caps plus a global byte cap. Handles use opaque random identities and reject foreign owners; explicit drop, owner disposal, idle expiry and plugin disposal release them. A Host restart loses these snapshots, not the operation's external effects.

Pages report their offset, unit, shown/total, next offset and final-page status. Array/record pages keep whole items; one oversized item requires JSON byte pages, whose UTF-8 boundaries preserve exact reconstruction. Measure the entire response and rendered output, including metadata, against the result budget. Complete immutable subprocess spill capture may be decoded only within its separate acquisition bound; a missing, truncated or oversized capture remains a coded failure, not an available result.

Native structured failures at `metadata.error` are forwarded as data, independently of a returned business record containing `success:false`. A failure does not authorize replay, rollback or an alternate-shell retry. The native strict default is not a file-policy setting or an agent-mode toggle.

## Model context

Keep seven tools: six independent execution/discovery/retrieval operations plus one `aether_session` with `action: open | eval | read | list | close`. Do not register aliases for the five retired session-tool names. Reject missing action requirements and irrelevant fields before session lookup or effects; preserve operation results, ownership, policy invalidation, partial effects and cleanup. Concise descriptions distinguish typed JSON data from AetherShell source, fresh processes from persistent state, canonical results from raw streams, and retained ids from job/session ids. Parameter text carries units and defaults; native signatures are discovered on demand. Do not add a duplicate system-prompt tutorial or omit final-denial, real-host-effects, same-job/no-replay, cancellation and owner-lifetime guidance to meet a byte budget. The assembled legacy and typed tool schemas have UTF-8 byte budgets and usage-rule tests in `tests/guidance.spec.ts`; generated snapshot sidecars remain aligned with those declarations.

## Compatibility

This build requires the fork's matching Host/tool-runtime build, which accepts undefined per-result presentation metadata. Package replacement alone does not upgrade an already running Host. The Host API cohort is DSH `0.2.1-rc.2`; legacy mode targets AetherShell `12.0.2`, and typed mode requires the capabilities implemented by the personal `12.0.2+ryan.2` runtime. The interpreter remains an external prerequisite and is not redistributed in this MIT-licensed plugin. Persistent sessions depend on the interpreter's own `sess_open`, `sess_eval`, `sess_usage` and `sess_close` builtins, which exist in the running interpreter but not in its published ontology, so no discovery result advertises them. An interpreter update requires real-binary verification of discovery, argument fidelity, pipelines, module evaluation, session state retention, session policy invalidation, background output and streaming, errors, and confinement before changing the supported protocol.

## Verification

From this directory, `pwsh -NoProfile -File scripts/run-local.ps1 typecheck`, `pwsh -NoProfile -File scripts/run-local.ps1 test`, and `pwsh -NoProfile -File scripts/run-local.ps1 build` exercise the checkout-linked source without installing dependencies or rewriting the root lockfile. After building, `node tests/built.smoke.mjs` checks actual Host runtime exports and `node tests/built-session.smoke.mjs` assembles the seven-tool interface against built provider artifacts without starting an interpreter; source-only tests cannot detect an erased const-enum value import in a bundle. The recorded scenarios in [aether-shell-native](../../snapshots/session/aether-shell-native/snapshot.yml), [aether-shell-typed-data](../../snapshots/session/aether-shell-typed-data/snapshot.yml) and [aether-shell-session](../../snapshots/session/aether-shell-session/snapshot.yml) pin query and unified-session tools through the shipped headless profile. Focused suites cover session ownership, state retention and per-handle isolation, the between-call read and its busy refusal, policy invalidation, deadlines and cancellation, background admission, raw output, kill settlement and cleanup, and the real Windows ACL refusal path through the installed interpreter. Tests own temporary directories and subprocesses and await cleanup before releasing them. Isolated-profile validation precedes real-profile activation; preserve profile configuration backups. Existing packages may be replaced through DSH package management while the Host runs; activation requires a restart because the current process retains its loaded module generation. Do not manually overwrite loaded module files or restart the Host as part of an install command.
