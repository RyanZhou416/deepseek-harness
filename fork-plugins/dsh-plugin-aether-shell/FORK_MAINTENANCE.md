# AetherShell plugin maintenance

## Behavior

This optional bundle exposes native operation discovery, positional JSON calls, structured pipelines, and AetherShell expression evaluation alongside the existing shell tools. It also adds owner-scoped persistent interpreter sessions while the live-agent registry is mounted, and one background-job starter while the job registry is mounted. It does not register or replace `ctx.shell`. Every interpreter process runs under the Host's subprocess provider and the calling Session's DSH file policy; the external AetherShell interpreter is not an authority for that policy. Sessions and background jobs introduce no Session format change and keep no code checkpoint: a session is one long-lived `ae agent interactive` process whose native variables, functions, current directory and environment live only in that process — isolated from other handles while the real host filesystem stays shared — and a job is one fresh interpreter process per program.

## Preservation rule

Keep the four query tools stateless and keep the session and job surfaces conditional on their registries, so a composition without `agents` or `jobs` never advertises a handle no controller can serve. Keep the session read a consuming drain of output written between calls, refused while a call is in flight, so output is delivered exactly once and never silently discarded. Preserve PowerShell and Bash bindings, and never silently retry a denied operation through another shell. Clear inherited AetherShell control variables before applying deployment settings. Keep request-data validation for the interpreter's JSON-to-source conversion: interpolation strings and unquoted record keys must not become unintended executable input. A session program keeps the caller's own interpolation by reaching the interpreter as an encoded string literal inside the native session call, while a background job program travels the command line exactly as `aether_eval` does, with no wrapper introduced; preserve that distinction when either channel changes. Keep the ownership rules: a session belongs to the exact live Agent that opened it, is refused to every other agent, is closed rather than reused when the caller's file policy changed, and is terminated when a deadline or cancellation stops an in-flight command because no state can be safely resumed. Keep a background job owned by the registry until it settles, keep `job_kill` a request whose settlement follows managed-process cleanup, and keep job output the raw structured-by-nothing streams rather than a decoded result document. Preserve explicit interpreter, response, cancellation, confinement and cleanup-failure reporting rather than treating process exit zero as a successful native call.

## Compatibility

The Host API cohort is DSH `0.1.7-rc.1`; the native protocol is exercised against AetherShell `12.0.2`. The interpreter remains an external prerequisite and is not redistributed in this MIT-licensed plugin. Persistent sessions depend on the interpreter's own `sess_open`, `sess_eval`, `sess_usage` and `sess_close` builtins, which exist in the running interpreter but not in its published ontology, so no discovery result advertises them. An interpreter update requires real-binary verification of discovery, argument fidelity, pipelines, module evaluation, session state retention, session policy invalidation, background output and streaming, errors, and confinement before changing the supported protocol.

## Verification

From this directory, `pwsh -NoProfile -File scripts/run-local.ps1 typecheck`, `pwsh -NoProfile -File scripts/run-local.ps1 test`, and `pwsh -NoProfile -File scripts/run-local.ps1 build` exercise the checkout-linked source without installing dependencies or rewriting the root lockfile. The recorded scenario in [aether-shell-native](../../snapshots/session/aether-shell-native/snapshot.yml) pins model-visible tools and results through the shipped headless profile. Focused suites cover session ownership, state retention and per-handle isolation, the between-call read and its busy refusal, policy invalidation, deadlines and cancellation, background admission, raw output, kill settlement and cleanup, and the real Windows ACL refusal path through the installed interpreter. Tests own temporary directories and subprocesses and await cleanup before releasing them. Isolated-profile validation precedes real-profile activation; preserve profile configuration backups and do not replace installed artifacts while the Host is using them.
