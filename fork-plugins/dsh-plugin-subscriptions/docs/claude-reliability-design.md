# Claude 订阅请求可靠性设计

**范围：完整设计目标，不等于所有目标均已实现。** 已实现能力、发布验证和保留差异由[实现状态](claude-implementation-status.md)统一说明；当前使用规则以 [README](../README.zh.md) 和所链接源码为准。本页不重复维护某台 Host 的安装状态。

## 摘要

订阅插件负责正确发送请求、可靠接收结果、尊重服务端拒绝，并解释账号为什么可用或不可用。本页覆盖五项共用规则：明确拒绝后停止、凭据与订阅池状态、流结束／错误／取消、集中协议配置、用户可见状态。[账号与策略维护设计](claude-account-maintenance-design.md)另外定义已纳入范围的三项能力：活会话认证维护、账号资料新鲜度维护、按实际资格获取托管策略。优先复用已有账号池、令牌管理、流翻译和设置页面，不复制整个 Claude Code，也不以更换身份或修改版本声明绕过拒绝。

研究参考只采用 **Claude Desktop 管理的 CC**：Desktop 2.19675.1 与其固定 CC 2.1.288 的相应一方路径。插件本身仍是 DSH 的 provider，不是被 Desktop 启动的 CC；Desktop 的父注入值、独立 CLI 的默认值、服务器实际部署值必须区分。模型请求由用户或既有 Agent 任务发起；新增维护仅限实际活会话相关的认证、资料与有资格的策略获取。本设计不新增遥测、实验平台同步、自更新、模拟保活、远控、runner、MCP 或内容包下载。

## 用户可观察的结果

| 遇到的情况 | 目标行为 | 用户看到的结果 |
|---|---|---|
| 服务端拒绝当前客户端版本 | 当前操作停止；不刷新凭据、不换号、不改 beta／版本重试；匹配的协议配置暂停新请求 | “客户端协议版本不再受支持，需要更新兼容实现” |
| 凭据明确失效或被撤销 | 只在允许的认证恢复分支刷新一次；永久失败后该账号退出可选集合 | “需要重新登录”，不是模糊的 24 小时配额冷却 |
| 真正可恢复的配额窗口 | 记录对应账号／模型范围与服务端时间；仅在安全重放条件下使用现有池策略 | “额度冷却到……”，时间未知则明确未知 |
| 回答或工具参数传到一半断开 | 已显示的部分保留为中断结果，不假报成功、不自动重放已提交输出 | “响应中断，未自动重试”；不完整工具调用不可执行 |
| 用户取消 | 停止等待、请求和后续恢复，释放本请求资源，不影响其他并行请求 | “已取消”；不把它记成账号不健康 |
| 更新协议配置 | 下一请求使用完整且自洽的新配置；在途请求保持原配置快照 | 显示实际使用的配置版本，不静默改变一条流的协议 |

“停止”指当前逻辑请求的所有自动恢复停止，不只是某个 HTTP 调用返回。用户手动再试是新的逻辑请求，但仍须经过账号和协议暂停检查；按钮不能变成绕过策略的后门。

## 现有基础与责任归属

本节是设计时的代码定位，不是运行验收。现有源码、用户的未提交改动及这些文件的职责均保留；实施时再次核对，不能从工作区文档推断已部署版本。

| 责任 | 当前可复用位置 | 本设计增加的义务 |

| HTTP／SSE 错误分类 | [common.ts](../src/providers/common.ts)、[anthropic.ts](../src/translate/anthropic.ts) | 同一拒绝在 HTTP、HTTP 200 内嵌 SSE 错误中产生相同决定；未知错误不默认当 `SERVER` |
| 重试与池路由 | [rate-limit.ts](../src/providers/rate-limit.ts)、[pool-health.ts](../src/providers/pool-health.ts)、[pool.ts](../src/providers/pool.ts) | 将“能否重试／换号”与“健康影响范围”分开；保留终止与输出提交信息 |
| 凭据选择与存储 | [accounts.ts](../src/providers/accounts.ts)、[store.ts](../src/auth/store.ts)、[claude-code-creds.ts](../src/auth/claude-code-creds.ts) | 复用单飞与条件写回，补齐身份／修订隔离和永久失效状态，不让迟到刷新覆盖退出或重新登录 |
| Claude 协议 | [claude-wire.ts](../src/providers/claude-wire.ts)、[claude-desktop.ts](../src/providers/claude-desktop.ts)、[claude-atis.ts](../src/providers/claude-atis.ts) | 聚合已有 wire profile 与 Desktop pin，不复制 beta 注册表；账号运行时 pin 单独管理 |
| 流与传输 | [sse.ts](../src/translate/sse.ts)、[anthropic.ts](../src/translate/anthropic.ts)、[claude-fetch.ts](../src/transport/claude-fetch.ts)、[bridge.ts](../src/transport/bridge.ts) | 明确响应终态、输出提交、工具参数完成与单请求取消；传输层不偷偷重发 |
| 状态与界面 | [rpc.ts](../src/auth/rpc.ts)、[SubscriptionsSection.tsx](../src/client/SubscriptionsSection.tsx)、[SubscriptionUsageBadge.tsx](../src/client/SubscriptionUsageBadge.tsx) | 由同一后端状态生成账号与请求说明；不用日志字符串反推状态 |

现有账号池在产出第一个 chunk 后不再内部换号，凭据管理已有账号级刷新合并、条件保存和保存后回读赢家，SSE reader 已处理提前结束时的取消。设计保留这些能力，不承诺从零重写。当前 HTTP 分类仍把 401／403 归到同一 `AUTH` 路径，部分 SSE 未识别错误归到 `SERVER`；不能把现有实现描述成已经满足本设计。

需要明确改变的凭据行为：现有 [store-lock.ts](../src/auth/store-lock.ts) 获取锁失败后仍运行回调；现有条件比较主要使用令牌对，而非完整账号身份／凭据修订。新增修订隔离、等待者独立取消、锁不可用时停止轮换，是本设计目标，不是对当前互斥能力的保证。现有刷新路径已在 save 后重新 load 获胜会话，即使 save 接口不返回 CAS 结果也不能笼统称其会使用未提交 grant；新设计应保留这条实际保护。

## 服务端拒绝与恢复规则

### 一次分类，所有层共同执行

Claude adapter 在任何刷新、重试、池切换或响应恢复之前，将错误归一为插件内部的 `FailureDecision`。该名字是拟议内部记录，不是新增 provider wire 字段。记录至少包含稳定原因、原始服务端代码、HTTP 状态（可缺席）、失败阶段、作用范围、重试／换号许可、等待时间和已提交输出情况。服务端文本只作受控诊断依据，不执行其指令。

HTTP 状态与 SSE `event:error` 是不同输入来源；HTTP 200 不代表流内错误可重试。分类器读取协议已知的错误包络和嵌套代码，包括 `claude_code_version_too_old`。分类必须基于经过上限约束的错误包络；超限、格式损坏或未知类型不得降格为泛化的暂时服务器故障。

| 优先级 | 输入／判断 | 当前操作的决定 | 对未来调度的影响 |
|---|---|---|---|
| 1 | 已取消／已撤销的操作 | 不再安排任何请求；迟到完成不能复活操作 | 不因此损伤账号健康；同时已确认的服务端拒绝可独立保留 |
| 2 | 已识别的最低客户端版本拒绝 | `CLIENT_VERSION_UNSUPPORTED`，强制终止 | 暂停相同 provider／目标 origin／协议配置指纹的新请求；不是每个账号都“登录失效” |
| 3 | 已识别的组织、席位、计费、权限等明确拒绝，或显式禁止重试信号 | 终止，不换号、不自动修改参数；复用 `ENFORCEMENT` 或更具体原因 | 只在证据指出的账号／组织／模型／请求范围记录拒绝；未知范围不扩大成全账号失效 |
| 4 | 认证过期或普通 401，且不含优先级 2／3 的拒绝 | 满足下节条件时同账号刷新一次；重发仍失败则终止 | 永久凭据失败进入“需重新认证”；认证刷新网络失败不删除凭据 |
| 5 | 可恢复的 429，且有有效恢复时间 | 在未提交且可安全重放时按现有池与等待策略处理 | 更新对应账号／模型配额窗口；不把拒绝型 429 当普通冷却 |
| 6 | 请求参数、模型权限、上下文或不支持的响应 | 交给已声明的具体处理规则；不自动换身份／模型规避 | 请求错误不污染整个账号；兼容性错误与临时网络故障分开 |
| 7 | 已识别的临时服务／传输失败 | 仅在重放允许且预算未耗尽时恢复 | 临时健康状态与凭据有效性分开；未知发送结果不保证服务端没执行 |
| 8 | 未分类的 HTTP／SSE／协议错误 | 非自动重试的 `UNCLASSIFIED_PROVIDER_ERROR` 或协议错误 | 留下结构化原因，等待用户或兼容更新；不默认为 `SERVER` |

优先级 7 的“已识别临时失败”必须有显式映射：本设计将无结构化错误包络的 HTTP 500／502／503／529 归为服务暂时失败，将 HTTP 408／504 归为超时；仍先检查已识别的拒绝与禁止重试信号，并再受安全重放条件限制。SSE 只将已列明的 `api_error`、`overloaded_error`、`timeout_error` 等映射为暂时失败，`rate_limit_error` 单独走配额／拒绝判断。带未知结构化错误类型的响应、其他未映射状态或错误体超出解析上限，走优先级 8，不能靠“有 retry-after”重新归为临时错误。空体／网关纯文本的已列明 5xx 因此与未知 SSE 错误有确定而不同的归属。

显式终止高于 `retry-after`、`x-should-retry:true`、beta 兼容调整、上下文恢复及池策略。同一响应同时含版本拒绝码和通用可恢复文本时，版本拒绝获胜。`retry-after` 只提供等待候选，不授予重试权限；终止响应不得在界面显示“自动重试倒计时”。普通无说明的 403 不触发认证刷新，也不据此删除令牌；按权限拒绝／未分类拒绝结束当前操作。

上述优先级是 Claude 路由目标。其他订阅 provider 的已声明配额／响应语义不能被 Claude 规则覆盖；共享记录和恢复约束可以复用，服务端代码映射必须各自实现并验证。

### 真正的端到端停止

只把新错误码排除在插件重试白名单外不够。[Host 重试执行器](../../../packages/llm/llm-retry/src/index.ts) 的 `always` 模式及其他恢复处理器可能重新发起整个模型步骤。实施需要以下最小集成义务，业务分类仍归订阅插件：

1. 插件输出一个可序列化的硬终止决定，拟议 Host 失败字段为 `retryDisposition: 'forbid'`；还包括下节的已提交响应导致的自动重放禁止。普通错误不隐含禁止或允许。
2. Host 在安排等待／恢复前以及真正执行自动重发前检查这个决定。`always` 模式、其他恢复插件和池路由都不能覆盖它；不能仅依赖监听器注册顺序。
3. [LlmFailure](../../../packages/llm/llm/src/types.ts) 的 thrown／finish 两种输入，经 runtime 归一和 Session 记录／恢复后必须保留该决定。新增字段属于未来通用失败语义，不在循环内写 Claude 专用错误码。
4. Host 在 LLM service 的只读能力描述中暴露拟议的 `failureRecoveryVersion: 1`，插件在 adapter 注册前检查；缺失或不支持的版本立即报 Host 兼容错误，不发送探测请求。该能力只能由同时实现失败归一、持久化保留、恢复调度和实际重发检查的 Host 发行版声明，不能由用户配置自报，也不能仅凭安装了重试插件推定。
5. 未支持该义务的 Host 不得启用宣称本设计保证的新版 Claude 路由；不能退回无限本地失败循环假装“已经停止网络”。公共能力字段和终止字段一起验收，不能只实现其一。

这是实施依赖而非本次代码变更。公共失败类型、持久化读取／投影和双方 SDK 若受影响，实施时按仓库的类型与会话格式规则独立确认，不能把它藏在一个插件 README 改动里。

同一逻辑请求只有一个恢复预算，包含认证重发、池切换和暂时故障尝试；认证恢复额外有“一次刷新周期／一次重发”的硬上限。复用已配置的尝试、冷却与等待上限，不再叠加一个隐藏的十次外循环。运输库自动重试必须禁用或纳入同一计数。用户取消在等待、刷新返回和实际发送前均重新检查。

## 凭据和订阅池状态

### 账号固定与刷新

每次逻辑请求选定账号后固定其稳定 key、身份与凭据修订。允许的换号创建新的账号尝试并重新组装该账号的凭据、wire-session、ATIS 和请求链状态；不能把旧账号的 pin 或续传状态带过去。独立账号入口维持“不静默换号”的既有规则。

刷新分支先释放被拒绝的响应体。同账号／同凭据修订单飞；等待者可独立取消，但一个等待者不能取消仍被其他操作需要的共享刷新。只有支持刷新、当前错误允许恢复且未交付输出时才进行认证重发。明确 revoked／invalid-grant、身份改变、没有可用 refresh grant 等情况不能无限刷新。

保存必须比较预期的账号身份与修订后提交，并返回存储中的获胜版本；CAS 失败不能继续用尚未提交的 grant。退出登录、删除账号、重新登录和源凭据替换提升对应修订，迟到成功／失败均不得覆盖或删除新版本。与外部 CC 凭据库的同步继续显式 opt-in；插件的单飞／锁不被宣称为与 Desktop 共用锁。

凭据存储是唯一写入所有者。读取状态、模型列表或用量徽标不应附带迁移／重命名保存；需要迁移时走串行写事务。跨进程锁未取得时，不允许继续进行可能轮换令牌的刷新／保存并声称具备互斥，必须返回可辨识的暂时繁忙或失败。刷新超时后即便后端可能已接受新 grant，也不得靠重复刷新旧 grant 猜测结果。

### 状态是几个独立维度，不是一个“绿灯”

| 维度 | 目标状态 | 退出条件 |
|---|---|---|
| 凭据 | `missing`、`ready`、`refreshing`、`reauth_required`、`source_changed` | 刷新成功只回到同身份的 ready；永久失败／身份冲突须用户重新认证或重新导入 |
| 配额／临时可用性 | 可尝试、配额冷却、临时故障、未知／过期快照 | 到达时间只恢复“允许尝试”，不宣告服务端已恢复；下一次真实请求确认 |
| 协议 | 当前配置可尝试、`upgrade_required`、不支持响应 | 不因重登、改账号别名或配额重置解除版本阻断 |
| 配置资格 | 已启用／移出池／模型不允许／账号已删除 | 由当前本地配置决定；不是网络健康问题 |

选池时求这些维度的交集。不能把所有错误压成一个 `coolingUntil`；也不能把模型级额度耗尽显示成账号密码过期。两个账号同时失败时，各自状态保留；池耗尽不应把版本／权限拒绝重新包装为可等待的 `RATE_LIMIT`。

永久凭据状态须依赖持久化的凭据存在性或身份修订标记，不能仅靠 24 小时内存冷却假装重新登录。协议拒绝用插件自有的少量非敏感状态保存，键为 provider、规范化目标 origin、协议配置指纹；它不写到对话正文，也不保存令牌。只有可信、经过兼容验证的新 profile 替换后，旧指纹阻断才不再匹配；不能仅改指纹字符串或声明版本号。同指纹的版本拒绝不提供“重新核验”或“强制重试”入口，普通重试按钮也保持不可用；重登、别名修改、清诊断或额度恢复均不能解除它。界面只提供查看诊断和正常宿主／插件升级指引，不做后台探测，也不靠重复点击重发已被拒绝的协议。

暂时额度／故障信息继续复用现有健康与用量数据；只增加表达缺失的维度，不另建一套评分器。状态读取和冷却到期不启动后台 provider 探测。登录变化只清它真正修复的凭据状态，不清别的账号、其他模型窗口或全局协议拒绝。

## 流完整性和重放边界

### 接收状态与终态

每个传输尝试由一个生命周期对象拥有 reader、abort、idle timer 和完成决定；不要分散成多个互相竞争的 done 标志。翻译器必须保留 HTTP 错误、SSE 错误、畸形消息、请求取消、空闲超时、完整终止与不完整 EOF 的区别。

| 输入／阶段 | 目标结果 |
|---|---|
| HTTP 非成功 | 在创建成功流之前分类，保留状态；先终止判断再考虑恢复 |
| HTTP 200 中 SSE error | 读取结构化错误及嵌套拒绝码，与 HTTP 分类一致；没有 HTTP status 不等于未知权限可重试 |
| 内容块与增量 | 校验块身份／类型／顺序，在受控内存内累积；工具 JSON 未闭合或解析失败不得成为可执行工具调用 |
| 完整 message 终止 | 检查要求的开始／块结束／停止状态，发出一次 usage 和一次 terminal finish；此后不再发块 |
| 尚未达到有效业务终态就 EOF、丢失必需尾帧或 reader 失败 | 返回 `STREAM_INCOMPLETE`／对应故障，标明已交付程度；完整终态后的正常 EOF 不新增失败，不能仅凭 EOF 本身判定成败 |
| 未知事件／停止原因 | 区分允许忽略的扩展与影响语义的未知；后者失败关闭，复用已有 `UNSUPPORTED_RESPONSE`，不自动续接不支持的服务端回合 |
| 调用方取消 | terminal aborted；停止本请求，丢弃之后的产出；idle 超时不能冒充用户取消 |

保留当前 refusal、生成上限、上下文超限的不同结果。输出被截断时抑制不完整工具，而不是回放已完成工具。协议 parser 的空行分帧规则不等于整个回答完成规则；两层分别验收。

### 自动恢复与可见输出

沿用并显式化现有池的保守规则：**第一个向 Host 产出的 chunk 之后，不在该逻辑请求中自动换号或重放整个模型请求**。这里包括 usage、reasoning、工具参数增量等非普通文本 chunk，不以“用户还没看到正文”豁免。这同时约束 Host 整步恢复，不只约束 `PoolBackedAdapter` 内部。用户要求重新生成时建立新请求，界面说明旧响应中断以及可能的重复计费，不把旧工具结果重新执行。

即使没有 chunk，发出去的 POST 也可能已经被服务器接受。将恢复候选区分为“未发送”“明确可重试的拒绝”“已发送但结果不明”；只有前两类或已证可安全重放的具体规则允许自动重发。不以重新生成 request-id 充当幂等性保证。跨账号切换还须确认不是明确拒绝、仍在同一用户允许的 provider／池范围内。

部分文本可以保留为带中断标记的显示内容，不能当作成功 assistant 历史继续拼接。工具可执行性必须等到完整的工具参数与该响应的有效终态，或 Host 已明确支持的安全流式工具协议；如果下游曾把增量当作执行许可，该消费者也必须纳入实施验收。

响应头中的 `request-id` 是服务端已响应的相关性事实，不是完成证明。[现有请求链](../src/providers/claude-wire.ts) 在收到头时记录 `cc_prev_req`；本设计不擅自把它改成“仅成功才记录”。协议配置明确这类 observed 状态的含义；assistant replay、工具完成和其他 completed 状态则只在各自提交点写入。所有状态按账号与 wire-session 隔离，迟到尝试不能覆盖新操作。

### 取消与资源释放

取消传播到 HTTP/Bun bridge 的本请求标识并唤醒阻塞 read；只调用迭代器 return 不能保证挂起读取结束。等待清理完成后再释放该请求的配额／reader／timer 引用。一个流的取消、背压或 malformed error 不能杀死其他并行流；共享传输死亡则让相关请求各自失败，后续新请求可以重建，但运输层不自动重放已发送请求。

取消和服务端拒绝可同时发生：请求界面可以以取消为最终状态，已确认的账号／协议拒绝仍作为独立事实保存。错误正文读取失败、取消清理失败不能掩盖最先确定的终止原因。

## 集中协议兼容配置

### 三层数据，不能混成一份配置

| 层 | 所有者 | 内容与更新方式 |
|---|---|---|
| 编译／发布的兼容 profile | 插件 Claude provider，组合外部 wire-compat 包 | profile ID／revision、CC 与 Desktop 版本 pin、端点角色与路径、header/beta 规则、请求能力、响应类型及拒绝映射；随插件可信制品更新 |
| 部署／用户偏好 | 既有 Config 与 provider settings 校验 | 池参与、模型允许列表、重试／等待上限、已支持代理和诊断选项；不能通过一个自由文本设置伪造受支持版本 |
| 账号／请求运行时状态 | TokenManager、wire-session 和请求生命周期 | 凭据修订、ATIS、request-id 链、当前配额及失败；按身份／请求隔离，不写回静态 profile |

新增 Claude profile 聚合模块，不将与 DSH ID 兼容有关的 `src/compat.ts` 误用为协议所有者。复用外部包已有 profile／beta registry；Desktop app version 是独立 pin，只在经过验证的组合中关联。Messages、profile、usage、bootstrap 和文件上传应按各自请求角色取规则，不能共享一份万能 header 集合。

每个逻辑请求在选定账号后冻结 profile 快照和指纹。配置更新只影响之后的操作；在途重试使用原快照，若该指纹收到版本拒绝则停止。远端 bootstrap／feature 值只能进入经过 schema 检查的运行时能力字段，不能改写目标 origin、OAuth client 标识、认证头作用范围或错误优先级，也不能下载执行新兼容代码。

初始化时检查版本组合、必需映射、能力与翻译器支持的一致性；未知组合明确报不支持，不“猜一个相近版本”。导出一份不含凭据的有效配置摘要供诊断。可信插件更新和用户配置变化是两条路径；不会新增后台自更新器或为模拟 Desktop 而发送未证必要的遥测／实验请求。

## 账号与请求状态展示

### 共用后端事实

扩展现有订阅 `status`／usage 投影和共享前端缓存，不让状态页为了显示状态触发新的上游请求。继续分离状态读取失败与登录／操作失败；“状态暂时读不到”不等于账号退出登录。后端从凭据、健康、协议与当前请求所有者计算视图，前端只按稳定代码映射本地化文案。

账号视图至少给出：稳定账号引用和别名、凭据状态、影响范围、原因代码、首次／最近发生时间、确切或未知的恢复时间、协议配置 ID、允许的下一步操作。多个模型窗口按自己的范围展示，不用最早或最长冷却冒充整个账号的唯一状态。

请求视图至少给出：本地逻辑请求 ID、当前尝试与原因、选定账号／模型、等待与取消状态、是否已交付输出、完整／中断／拒绝／取消结果、已知服务端 request-id。区分“未发送”“已发但结果不明”“已有部分响应”；不知道就写不知道。

### 界面与操作

| 位置／操作 | 目标约束 |
|---|---|
| 设置 → 订阅 → 账号卡片 | 显示需重登、冷却、权限拒绝、协议待更新等不同状态；保留已有账号别名／池配置 |
| 当前请求状态 | 显示选择账号、刷新一次、等待重置、已停止、响应中断等；同一原因不持续弹 toast |
| 用量徽标 | 只给简短状态并链接详情，不把读取用量失败显示成“额度已用完” |
| 重新登录／重新导入 | 只修复选定账号凭据；不清协议版本拒绝、不自动重放之前失败的请求 |
| 重试 | 只对允许的新用户操作开放，显示所选范围；协议版本阻断期间禁用。不会强制清健康状态、改版本或自动连试所有账号 |
| 复制诊断 | 仅导出允许字段和固定本地化说明，不导出完整请求／响应或 token |

新的 RPC 状态字段与错误代码需要同一版 host/client 共同更新；字段缺失不得前端回退为“健康”。使用现有 locale 字典、设置卡片和请求展示接口，不另起监控页面或轮询服务。历史请求信息优先由已有 Session 请求／失败／重试记录投影；不在插件另存完整对话副本。

### 诊断与隐私

默认允许记录 provider、账号内部引用／用户别名、模型、profile ID、错误代码、HTTP 状态、经过长度控制的 opaque request-id、时间和恢复决定。默认不存 access/refresh token、Cookie、Authorization、原始机器标识、带查询参数的完整 URL、提示、工具参数、正文片段或任意服务端回显文本。

错误 body 可在内存中按明确上限解析，仅提取允许的结构化字段；原始 body 不能通过 `cause`、warn 回调、RPC detail、模型可见错误或诊断导出旁路保存。服务端 message 可能回显敏感输入，默认文案采用本地模板。调试模式也不放开凭据记录；若需要更多诊断，使用独立显式选项和字段白名单，不自动上传。

协议／凭据永久状态保存在插件自己的版本化最小状态中；暂时状态沿用现有有界健康缓存。请求状态由正在运行的操作或已记录事件拥有，晚到失败不能覆盖重新登录后账号视图或另一请求的结果。界面读取不延长冷却、不刷新凭据、不提交迁移。

## 新增三项维护能力

[账号与策略维护设计](claude-account-maintenance-design.md)规定活会话绑定、认证定时续期、资料完整度／24 小时新鲜度、托管设置的实际资格、缓存和应用。三项都受本页硬终止和身份修订约束；它们不是额外遥测或全池保活，也不能借后台任务绕过用户取消。

账号资料获取沿用现有 profile 接口但保留结构化失败；策略获取仅在真实资格成立时运行，明确 pro/max 与订阅元数据 null 分开处理。维护结果使用既有状态投影显示，不让打开设置页触发新上游请求。涉及远端策略限制时必须连接真正的 Host 执行消费者，不能只下载后忽略。

## 实施顺序和验收

下面列出完整目标的验收要求，不是已通过测试的清单；实际执行结果以[实现状态](claude-implementation-status.md)为准。部署需要另行授权，源码变更与已安装制品分开验收。

1. **统一失败决定与硬停止**：先给 HTTP/SSE 同类拒绝一致的结构化结果，再连到池、Host 恢复与最终发送前检查。Host 不兼容时拒绝启用保证，而不是退化运行。
2. **凭据与健康投影**：保留账号固定和刷新单飞，加入修订隔离／永久状态，明确请求、账号、模型、协议四类作用范围。
3. **流提交与取消**：把已产出后的禁止自动重放落到 Host 和插件两端，验证工具参数与终态、并行桥取消及资源清理。
4. **协议聚合与状态 UI**：先建立自洽配置快照，再投影结构化账号／请求状态和脱敏诊断；状态读取不加后台流量。
5. **账号与策略维护**：在前述共用规则上接入活会话续期、资料新鲜度与有资格的策略获取；[专项验收](claude-account-maintenance-design.md#实施与验收)覆盖调度、取消、资格与策略执行，不提前引入未受控的轮询。

| 验收场景 | 必须观察到的结果 |
|---|---|
| HTTP 400 版本码 + retry header + clear-at 可恢复文本 | 版本拒绝优先；只有原始尝试，无刷新／换号／beta调整；Host `always` 也不得重放 |
| HTTP 200 SSE 内同一版本拒绝 | 与 HTTP 版本拒绝相同；不落到可重试 `SERVER`；已有输出保持中断标记 |
| 裸 503／504 带 retry-after，或 SSE 未知错误类型 | 前者按已列明的服务／超时规则分类后再检查重放资格；后者终止，不因相同等待头变成临时故障 |
| 403 权限拒绝／组织封禁 | 当前请求停止；不假刷新，不从同池另一账号绕过；作用范围不无依据扩大 |
| 并发 401 与同账号刷新 | 一次刷新周期；各请求最多一次授权重发；取消一个等待者不破坏其他等待者 |
| 刷新期间 logout／新登录／身份替换 | 迟到 grant 或失败不能恢复已退出账号或覆盖／删除新凭据；返回存储获胜版本 |
| 暂时刷新网络失败／永久 invalid-grant | 前者保留凭据并报告暂时不可用，后者需重登；不混成配额冷却 |
| 锁未取得／旧迁移与新写并发 | 不无锁继续轮换；状态读取无保存副作用；迁移走串行写路径 |
| 有有效恢复时间的 429／无恢复时间的拒绝型 429 | 前者仅在安全重放时等待／池切换；后者立即停；账号／模型范围与界面一致 |
| 同一响应分为任意字节块、多行 data、UTF-8 半字符、尾帧无终止 | 分帧一致；缺失业务终态不成功，不输出可执行的不完整工具 |
| 部分文本／工具参数后 EOF、SSE error 或超时 | 不自动换号或重放；保留部分显示但不提交成功历史／工具执行 |
| 两个并行流，取消其中一个／一个触发背压 | 只影响目标请求；底层 read 能退出，timer／reader 清理完成，终态一次 |
| 原 response request-id 已记录但流失败 | 诊断／协议相关性与成功产物分开；不凭头标成功，不跨账号污染 |
| profile 更新与在途请求、旧版本阻断重启 | 在途快照稳定；同指纹阻断不因重登／重启消失；可信新 profile 与伪改版本区分 |
| 阻断期间连点重试／并发新请求；Host 能力缺失 | 相同被拒 profile 不发送请求；缺 `failureRecoveryVersion` 的 Host 在注册时失败，不能靠恢复监听器次序蒙混启用 |
| 状态页面、徽标、复制诊断、断线重连 | 原因／范围／时间准确；没有额外 provider 请求，无 token／正文泄漏 |
| 原有其他 provider 与图片／视频工具 | 不被 Claude 新映射误改；本轮五项保证不暗中覆盖独立工具调度策略 |

实施检查应从真实 provider → pool → Host runtime/retry → Session 投影 → UI 路径构造合成输入，断言“没有发出第二次请求”和“没有执行工具”等外部效果；只测 classifier 返回值不够。复用现有账号、请求控制、流边界、transport bridge 测试和 keyless Session 场景；测试须隔离 DSH_HOME，不读取真实凭据。新增用户可见状态还须有真实 Loader 组合的离线场景和中英展示验证。部署／真实订阅测试是另一个显式授权步骤。

## 边界与未决项

- 五项规则先落实到 Claude 一方订阅对话路由；其他 provider 的共享终止／提交义务可以采用，但每个 provider 的错误映射和工具调度必须单独验收。
- 本设计不假装插件就是 Desktop-managed CC，也不要求模仿全部后台流量；固定版本用于已知兼容基线，服务器未来变化仍需受控更新。
- 新增 Host 硬终止字段及其存储兼容性是实施前的明确依赖；若无法提供，不得把“默认白名单不重试”宣传成不可绕过的终止保证。
- 请求提交事实需要从 Host 真实输出／日志所有者取得；本设计选择保守的首 chunk 边界，不将“尚未看到文本”当作可以任意重发。
- 协议阻断记录与凭据修订的具体存储 schema、迁移方式及公开类型名称在实施合同中定稿；行为与验收不允许因改字段名而削弱。
- 当前工作区已有未提交实现改动。本设计是目标规范，不等于对这些改动逐条通过审阅，也不声明未运行的测试通过。
