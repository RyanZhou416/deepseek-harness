# Claude 账号与策略维护设计

**范围：完整设计目标，实施与验证状态另列。** 本设计补充[请求可靠性设计](claude-reliability-design.md)，定义活会话认证维护、账号资料新鲜度维护和按实际资格获取托管策略。已实现能力、发布验证及保留差异见[实现状态](claude-implementation-status.md)；这里不把设计目标或源码变化当作安装完成的证明。

## 摘要

插件复用已有 token 与 profile 请求，在实际使用的账号上维护认证和资料；只有策略资格成立时才获取托管设置。后台动作由活会话、身份修订和明确状态拥有，不因打开设置页、列出模型或查看额度而启动全池轮询。所有请求遵守主设计的硬拒绝终止、同账号刷新合并、条件保存、取消和诊断脱敏规则。

## 范围与已确认事实

兼容参考固定为 Desktop 2.19675.1 管理的 CC 2.1.288 win32-x64，一方个人订阅、普通 local-direct 子进程已启动。源码静态审查确认：认证供应／维护没有保留原会话能力的关闭选项；子 CC 的 profile 检查在资料缺失或超过 24 小时新鲜期等条件下自动获取，没有独立可达关闭选项；托管设置须按实际订阅元数据判断，不能仅按“个人账户”标签排除。缓存命中或失败可继续不是用户关闭方式。

该范围内，普通事件上报、专用错误上报和内部 metrics 均有已接通的关闭路径；CC 子进程自更新由父固定写入 `DISABLE_AUTOUPDATER=1`。**本设计不增加遥测、错误上传、实验平台同步、自更新、模拟保活、远控或素材包下载。** 不将上述子进程结论扩成整个 Desktop 父程序的遥测／更新都可关闭。

现有 [Claude provider](../src/providers/claude.ts) 已有 OAuth refresh、登录时 profile 获取和 UUID 缺失时补资料；[TokenManager](../src/providers/common.ts) 已有按账号刷新合并、保存后回读获胜版本。[插件注册](../src/index.ts) 已连接这些接口。新增工作在调度、元数据采用和策略处理，不再建立第二套凭据存储或相同端点客户端。资料 profile 与主设计中的“协议兼容 profile”是不同概念，字段和界面不得混名。

## 共同生命周期与状态

Claude provider 持有每个规范化账号的一份维护状态。身份键由稳定账号引用与已确认组织组成；凭据修订、协议配置指纹和维护任务代次分别校验。令牌本身不作日志键。账号、组织或 provider origin 改变时，旧缓存不能被带到新身份；有效 token 轮换可以保留同身份资料，但迟到响应必须先验证身份／任务仍有效。

“活会话”是已实际选择该账号、尚未释放的运行时 Claude 会话绑定，不是磁盘上的历史 Session、模型菜单或账号列表。第一次实际路由使用建立绑定；流结束不必销毁仍存活的会话绑定，因而等待下一条提示期间可维护认证。会话关闭／卸载、用户停止该会话、账号解绑、退出、身份替换或插件销毁释放绑定；剩余绑定为零就停止该账号的定时维护。重启后不凭历史 Session 自动恢复绑定。

同账号多个会话共用维护任务和有界缓存，不共用会话正文。移出自动池仅停止新的自动选择，不偷偷切换已经明确绑定的账号；明确禁用／删除账号才释放其全部绑定。一个请求取消只撤销自己的等待，不能取消其他活会话仍需要的共享刷新；用户停止整个会话则释放该会话绑定。

每项请求在发送前、结果提交前、下次调度前三处检查绑定、身份和终止状态。重试、退出和插件 dispose 都须等待所属工作清理，不让 timer／迟到 Promise 重新注册任务。读取状态不获取绑定，不刷新、不延长冷却，也不保存迁移。明确服务拒绝使用主设计的作用范围：只停相关账号／协议／操作，不把普通资料失败扩成所有账号封禁。

## 活会话认证维护

### 触发和资源所有权

账号存在活绑定、刷新来源支持主动维护、token 有有限可信到期时间，且该 provider／origin／协议指纹没有已生效硬终止时，安排一次到期前任务；成功采用新 token 后重排，而不是固定间隔 ping。到期未知时标记未知，保留请求时的认证检查，不编造到期时间或启动立即重试循环。借助持久化凭据恢复的是认证数据，不是历史 timer。

调度任务、请求前检查和普通 401 恢复必须进入同一个账号／凭据修订的刷新入口。进入任务后先回读存储：其他请求已经刷新到足够新的 token 就不再请求。当前接口具有 grant 时复用 `refreshClaude`；显式外部凭据同步仍遵守原 opt-in，不假装共享 Desktop 的锁或直接写其存储。

同一插件的合作实例跨进程使用同一插件凭据库时，必须在轮换前取得同一插件刷新所有权，再回读凭据；仅保存时加锁不足以防止两个合作实例同时花费旧 refresh grant。所有权取得失败或失效时不继续发轮换请求；保存仍需身份／修订条件检查。此规则与主设计的“不无锁继续轮换”共同验收。

上述锁不约束 Desktop／CC 等外部持有者。对仍由外部管理、尚未建立来源级协调合同的共享导入凭据，不启用本次新增的定时轮换，状态明确说明该来源未支持主动维护；不能无限报 busy，也不能把回读／CAS 宣称为与外部严格互斥。已有按需导入、刷新及显式同步仍遵守其身份核验和写回约束；要启用主动维护，实施任务必须先明确该来源的刷新所有者或改用插件独立管理的授权。

### 结果与失败

- 成功返回的 token、scope 和到期时间先验证，再条件保存；以存储中的获胜版本供后续请求。后台续期不会重发已有模型请求，也不假称已经建立的 HTTP 流更新了 Authorization。
- 可确认的暂时失败可在配置预算内重排；仍有效的旧 token 只有在重新核对身份和到期后才可继续用。到期后不得继续发送旧 token，也不得凭刷新超时假设 grant 没被使用。
- `invalid_grant`、撤销、身份冲突或明确终止停止对应维护，投影需重登／冲突／协议拒绝状态；不能轮换其他账号来替后台刷新“恢复成功”。
- 最后一个绑定释放时清 timer；已发出的刷新以取消和条件提交规则处理，不能因网络层不可撤销而复活账号。共享任务的最后一个等待者与是否仍有活绑定分别判断。

提前量和有限重试预算是经过校验的部署 Config，默认提前量复用现有 `CLAUDE_PREEMPT_MS` 的五分钟基线，不在另一个模块复制常量。这个默认是插件设计选择，不冒充 Desktop 所有远端 flag 的生产值。调度失败和模型请求失败分别记账，不能产生两个相乘的重试循环。

## 账号资料新鲜度维护

### 获取条件与采用

绑定初始化时检查该账号资料；以后有真实账号使用且缓存已过期时再检查。不建立“每 24 小时唤醒整个池”的永久任务。24 小时是固定客户端的资料新鲜度基线；新设计将其作为有效 Config 的默认值，与现有元数据缓存约束一致校验。

资料缺失／不完整、成功获取时间超过新鲜期或身份已变化，且授予的 scope 包含 profile 能力、有可用 token 时，合并一次 `GET /api/oauth/profile`。没有相应 scope 时显示“不具备资料读取权限”，不重复失败请求。登录已有成功结果可填同一缓存，UUID 补全也共享该读取，不能各发一次。

资料对象与令牌对象分开保存。资料记录只保留消费者实际需要的账号／组织身份、订阅／计费元数据、成功时间、完整度及来源修订；不保存原始 profile body。完整度按当前协议支持字段检查，可从账号创建、订阅创建和 onboarding 字段是否有效得出，不等于必须把全部字段都长期存下来。

订阅类型必须来自经验证的响应映射或既有可信凭据元数据，不能把产品名、账号别名或空字段猜成 pro/max。缺席字段不删除已知值；显式 null 的语义按该字段协议处理。资料缓存新鲜度与已确认订阅类型的有效性分开：仅超过 24 小时或资料刷新失败，不把身份未变的已确认 pro/max 自动改为未知；否则会新增原资格明确排除的策略请求。

先验证响应身份，再采用非敏感资料。账号 UUID／组织与当前绑定不一致时，不把它当普通资料更新混入旧账号，应拒绝提交并报告身份变化。普通 token 轮换但身份一致时可按重新读取的修订安全合并；退出／新登录／组织切换后，旧响应不得写回。成功且资料有效才推进成功时间；部分响应和失败不得伪造新的完整缓存。

### 失败不等于认证失效

网络失败、超时、无效或不完整资料保留同身份旧资料并标 stale／unavailable，按有限冷却合并下次真实触发，不自动让池换账号或无限重试。已有足够认证与 wire 身份时，这类后台资料失败不阻止会话。若插件构造正确请求确实缺关键账号 UUID，仍执行原身份错误规则，不能用“资料可失败继续”伪造身份。

普通 401 可复用一次受控认证恢复；明确凭据撤销／版本／权限拒绝由统一失败分类先处理。现有 profile helper 把非成功结果压成空对象的形式需要扩成结构化结果，至少保留取消、暂时失败、资料缺失、身份冲突和明确拒绝的区别，不能让新的硬终止规则在此丢失。

## 按资格获取托管策略

### 资格输入和触发

仅支持所选一方 OAuth 订阅路径；不会为构造资格而读取独立 API key、开发者覆盖或切换 gateway。启动绑定时先按其真实元数据计算资格，再建立相应获取／刷新任务。资格与账号身份共同标记，账号或组织变化使旧结果失效。

| 实际输入 | 新设计行为 |
|---|---|
| 已确认、可用于当前绑定的 pro/max，且无独立 API-key模式 | 不建立本托管设置 GET／poller；这不是“父有快照所以替代请求” |
| 有效 OAuth，订阅类型 null／缺失或无法可靠确认 | 进入已证未知订阅资格分支，不用账号显示名推断个人套餐；具备正确认证后获取策略 |
| Team／Enterprise 或其他未纳入该个人基线的类型 | 不冒充 pro/max；只有协议映射明确支持并经过验收才采用该资格分支，否则说明适用性未支持，不静默绕过 |
| 无可用认证／账号已撤销 | 走认证失败，不发送无认证探测、不改用别的账号试取政策 |

明确 pro/max 判定必须附带匹配的身份与来源修订；普通 token 轮换不自动使同身份类型失效。只有账号／组织／origin 改变、类型来源被显式撤销或有效新响应将类型置为未知时，已知类型才转为未知；profile 缓存到期、暂时失败或缺席字段均不触发这一转换。首次绑定可以复用已有有效元数据，也可以共享一次有界 profile 获取；始终没有已确认类型时按 unknown 处理，不能因资料失败伪造 ineligible。取得可信 pro/max 后可停止后续 poller，但不能为停止请求而改配置标签。

资格成立、绑定仍有效且没有适用于该 provider／origin／协议指纹的硬终止时发送 `GET /api/claude_code/settings`，认证和请求头来自集中协议配置的独立 settings 角色，不挪用 Messages 的全部 headers。以账号、组织、origin 与协议指纹隔离单飞、checksum 和缓存，读取状态页不触发获取。已启动的活绑定才维持刷新；默认周期参数采用已读客户端一小时基线，但不保证一小时内必生效，失败退避和预算由配置校验。取消或最后绑定释放停止调度。

### HTTP 结果与缓存

| 结果 | 目标处理 |
|---|---|
| 200 且有效设置 | 校验包络和支持字段；在同身份／任务仍有效时提交策略快照，随后发布状态；接收不等于已同意或已执行 |
| 固定 settings 端点的 204／404 | 采用该端点已核的空策略成功语义，仅更新同身份远端策略快照；本地／父策略限制和已记录的硬拒绝不被清除，实际生效仍经过策略应用规则 |
| 304 | 必须对应实际发送的 checksum 和同身份有效缓存；缺缓存的 304 是错误，不能当空策略 |
| 网络失败／超时／临时 5xx | 保留同身份已接受快照并标 stale；无快照时标 unavailable，不授予任何新能力，按有界退避处理 |
| 畸形、所有规则均无法安全采用或影响权限但未支持的设置 | 保留旧快照并显示明确的策略兼容问题；无法判断相关限制时暂停受影响操作，不能悄悄丢掉限制继续 |
| 明确拒绝、401／403 | 先统一分类；允许的普通 401 仅同账号刷新一次。明确拒绝不重试／换号，原缓存不能覆盖新拒绝 |

204／404 的空策略映射是固定 CC 的 settings 请求处理器已采用的端点专用规则，不是通用 HTTP 规则，也不是新增猜测。只有已配置的第一方 settings 请求、身份与目标均匹配时采用；重定向或明确来自本地代理／错误目标的失败不得套此映射。空远端快照可能撤销先前的远端限制，但不能清除本地或其他来源限制，不能把“撤销远端限制”直接当作获得新的用户授权。

普通网络不可用不是服务端允许，也不自动等于服务端拒绝。在已有可靠认证／身份且没有已知禁止时，可继续不依赖新授权的既有会话操作；需要新增权限或尚待同意的操作保持等待／拒绝。暂时无法取得策略不能清除已知限制；明确拒绝才按主设计终止相应请求与后续自动恢复。

### 策略应用与 Host 权限

维护端只生成经过验证的策略投影，不能把远端 JSON 直接合并进 Cordis Config、环境变量、工具目录或执行器。远端策略不能扩大本地已批准权限、改变认证目标或触发插件下载。对已支持的限制，在具体操作执行前实施；涉及新的用户同意时使用现有同意机制，不将静默获取或 verified 状态当用户授权。

协议配置需为每个采用的策略键登记消费者、范围与不支持处理；仅下载成功但没有消费者不算完成实现。对可能影响安全的未知限制，显示 `POLICY_UNSUPPORTED` 并暂停受影响操作，而不是忽略。如果实际消费者由 Host 所有，实施合同必须纳入该消费者；插件不能靠前端提示代替执行检查。父 `managedSettings`、远端 API 策略和本地用户权限是不同来源，不互相冒充。

获取按账号合并，应用按会话／操作计算。新策略限制影响后续操作；对在途操作，只有既有执行器支持安全取消时才请求取消，不能声称所有外部效果已撤回。新快照不得与旧会话授权错误拼接；模型可见行为若因此变化，必须经过主设计所要求的可重建 Session 记录。

## 配置与用户可见状态

本设计不暴露“忽略服务拒绝”或“强制跳过有资格策略获取”的开关。部署可配置提前量、资料新鲜期、策略周期、超时和有限失败冷却；零／负值不得被偷偷当作禁用。保持主设计“误配置明确失败”的规则，不复制未核实的 Desktop flag 生产值。

账号状态增加资料 fresh／stale／missing、策略 ineligible／loading／current／stale／unavailable／consent-required／blocked，以及下一次有效维护时间。状态仍由各自所有者计算；“资料暂时取不到”不显示为账号失效，“不适用策略 GET”不显示成获取成功。所有维护失败带操作种类及作用范围，诊断不包含 token、完整 profile／策略原文或对话正文。

前端读取沿用现有共享缓存和本地化文案；不新增隐藏全池探测。明确停止会话、退出账号、卸载插件会停止相关维护；一个会话取消不会停止其他会话的账号维护。无活绑定时仅保留数据，不保留网络任务。服务器不能借这三项维护新增本设计范围以外的连接。

## 实施与验收

本表是完整设计的验收要求，实际执行结果以[实现状态](claude-implementation-status.md)为准。先复用主设计的身份修订、终止决定和存储事务，再接维护生命周期；随后接资料与策略投影，最后接用户状态。策略键映射和实际 Host 执行检查在同一实施任务内完成，不接受“先拉接口、以后处理限制”的半成品。

| 场景 | 必须观察到的结果 |
|---|---|
| 打开设置页、模型选择器，或只有历史 Session | 无维护绑定、无新增 token／profile／settings 网络请求 |
| 同账号两个活会话接近到期，另有 401 | 共享一个符合条件的刷新周期；普通授权重发仍各受一次上限，不叠加任务重试 |
| 结束一个／最后一个会话，或 token 在排程后被替换 | 前者不影响其他绑定；最后释放清 timer；旧任务回读新版后跳过多余刷新 |
| 用户停止、logout／身份替换与刷新返回竞争 | 不复活旧绑定、不污染新身份；清理完成后不再调度，取消不变成账号故障 |
| 合作插件实例跨进程竞争同一 refresh grant；另有外部共享来源 | 合作实例刷新前取得所有权并回读，失败者不无锁轮换；没有来源协调合同的外部共享凭据不启动新增定时轮换，并显示原因 |
| token 到期未知、已过期、暂时刷新失败、永久失败 | 四类分别处理，无零延迟循环、不发过期 token；只有明确永久失败需重登 |
| profile 完整且新鲜／超过 24 小时／缺字段／scope 不足 | 新鲜不请求，过期或缺字段合并一次有界读取，scope 不足不循环；不是周期唤醒全池 |
| profile 失败、部分结果、组织变化或 token 并发轮换 | 成功时间不伪更新；身份一致才采用，暂时资料失败不清凭据，显式拒绝不被空对象吞掉 |
| 明确 pro/max 的资料缓存过期／失败，与真实 null 类型 | 已确认同身份 pro/max 不因资料 TTL 过期而新增策略 GET；真实未知才走相应资格分支，不靠个人账号文案省略 |
| 200／204／404／304 和缺 checksum 的 304 | 区分新策略、明确空策略、复用和错误；缓存按账号／组织／origin 隔离 |
| 策略已缓存但新请求网络失败，或返回明确拒绝 | 前者标 stale 保留已知限制；后者终止，无重试／换号，不让旧缓存覆盖新拒绝 |
| 未支持的权限策略、需同意策略、远端扩大权限 | 显示不支持或待同意；执行端阻止相关操作，无任意配置合并／下载／代码执行 |
| 条件从 null 转为可信 pro/max、账号切换及旧 poll 返回 | 重算资格并停止不适用调度；旧身份／代次不能写回；变化不会自动重放模型请求 |
| 确认使用本设计但未开启遥测／实验／更新能力 | 抓取合成请求记录中只出现本设计与会话所需连接，没有模拟日志、保活或更新请求 |

测试使用隔离的 DSH_HOME、合成 HTTP 响应、可控时钟和真实 provider／池／Host 组合，断言请求数量、取消后无请求、缓存采用和执行拒绝；不使用真实订阅凭据。测试日志和 UI 断言中同时验证三类状态及隐私字段。实际端点验证、安装或部署均需要另外授权。
