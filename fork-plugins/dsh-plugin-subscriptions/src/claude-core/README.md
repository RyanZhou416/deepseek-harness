# claude-core — shared pure single-account protocol core

English | [中文](README.zh.md)

`src/claude-core/` is the **pure single-account protocol implementation** for `policy_limits`, organization-pin validation and quota observation, shared by the DSH subscriptions plugin and the Mac pool VM. It **does not depend on DSH/Cordis**, does not import `src/providers/**`, builds no credential store, account pool or proxy of its own, writes no session data, and starts no timers.

## Module responsibilities

| Module | Its only responsibility |
|---|---|
| `policy-limits.ts` / `policy-limits-client.ts` / `no-live-policy.ts` / `policy-registry.ts` / `eligibility.ts` | Canonicalization, verdict table and bounded reads for the `policy_limits` document |
| `control-requirements.ts` | Tri-state control obligations of an adopted document: reads only `restrictions` and answers only "is this obligation in effect", never "is this allowed" |
| `org-pin.ts` | Tri-state parsing and validation of the organization pin (a bodyless POST is sent only when a pin is present) |
| `quota-observation.ts` | One read of one raw source and two projections: header family → legacy report / strict observation; raw usage JSON → legacy windows / strict observation. **It is the single parsing owner for those two sources**; neither the plugin nor the Mac side keeps a second copy of the rules |

Control obligations come from the `restrictions` of the server's `enforce_`/`require_` family, **not from keys of the 34-key allow registry**: `controlRequirements(document)` reads only `restrictions`, yields three states (`allowed:true` ⇒ `active`, `false` ⇒ `not-enforced`, absent key ⇒ `unknown`; a non-boolean makes the envelope parser `parse_failed` the whole document and **must not** be downgraded to `unknown`), and lists the active items this build has no consumer for in `unsupportedActiveControls` (distinct, fixed order). This build has no device-enrollment / cloud-create / link operation and no proven web_search / MCP connector executor, so an active control produces only this one state fact: **it by itself produces no refusal, parks nothing and changes no existing restriction path**; the real enforcement binding belongs to P6-host.

`KNOWN_CONTROL_KEYS` / `isKnownControlKey(key)` is **one and the same** classification: the two proven obligation keys are excluded from the **operation-permission key namespace** (the owner's live `restrictionKeys` and the persisted projection's unknown-key count share it), so they are not taken for unknown operation keys and do not refuse Messages/tools; it is **not a prefix rule** — `require_`/`enforce_` keys other than those two, and any other genuinely unknown key, still take the existing conservative path of refusal and counting. A persisted record retains no control state, so after a restore a control stays `unknown` (never shown as `false`); only counts, and old snapshots that cannot be attributed to their original keys, **keep their original conservative state** until the existing read path obtains a new real document.

The port boundaries of `quota-observation.ts` (a Mac-side reuse of the same strict output must register them together):

- `QuotaHeaderSource = { get(name): string \| undefined }`: a read-only source. A `Headers` instance can be passed directly (the adapter folds `null` into `undefined`, never the reverse into `''`).
- `LegacyResetResolver = (rawText: string \| undefined, now: number) => number \| undefined`: the injected port of the legacy projector. **The five forms — delay / duration (`6m0s`) / HTTP-date / epoch seconds / milliseconds — are decided by this port**; the core neither imports nor copies that algorithm, and `now` is injected by the caller.
- `parseUsageJson(body, now, options?)`: reads and projects only shapes this module already has evidence for, and takes **no caller-injected identity set** — a display name is not an identity, so an approved-id port is neither needed (nor any longer accepted). A numeric header reset is converted to milliseconds only as `epoch-seconds` (strict's single seconds→milliseconds conversion), and strict reading of the usage JSON's `resets_at` recognizes only the RFC3339 subset this module verifies — **a numeric reset must not be interpreted as seconds on that path**.
- Cross-read freshness / watermark / "updating one window does not renew another" belong to the caller (the plugin's `captures`, a future Mac's state): the core produces **per-read** facts only and builds no cache.
- `scopeKind` is a **required** dimension of a strict observation, taking only `'account' | 'model-family' | 'unknown-scope'`, and separate from the window token:
  - header: `5h`, `7d` = `'account'` (the general windows of the current authentication context); **`7d_oi`, `overage` = `'unknown-scope'`**. `7d_oi` is `seven_day_overage_included`, which the client stores under an independent key and whose applicability is conditioned on the model display list — it **must not be merged into `7d`, must not override the account weekly window or be min/max'd with it, and keeps its own reset and `observedAtMs`**; the applicable surface and period of `overage` are unproven.
  - usage JSON top level: only the mapped `five_hour`/`seven_day` are `'account'`; **`seven_day_opus`/`seven_day_sonnet` are `'model-family'` and carry a lowercase `family: 'opus' | 'sonnet'`** (the source client really does classify by catalogue family), which states only that this is a family window — it **does not decide for the consumer which model the current request uses**, and it is not a stable model id.
  - `limits` rows: `session`/`weekly_all` = `'account'`; `weekly_scoped` keeps the token `7d` but has **no stable binding ⇒ `'unknown-scope'`**; an unrecognized kind ⇒ `kind:'unknown'` + `'unknown-scope'`.
  - **Each observation is produced by its own source element**: two `weekly_scoped` rows stay two even when label, reset and `scopeKind` are all identical, and **any deduplication by `(kind, scopeKind)` is unacceptable**. A missing `family` never means account.
- **Recognized but unmapped top-level keys (`seven_day_oauth_apps`, `cinder_cove`) produce no window and no observation**: their applicable scope, period and channel are unevidenced, and "not a model window" does not mean "the all-account window of the current request", so they **produce an observation under neither `account` nor `unknown-scope`**; they only count one `window-key-unsupported` when they appear and are counted in `rejectedWindowKeys`, while legacy ignores them exactly as before.

Authoritative sources: `R/phase34/business-followup/policy-limits-implementation/{contract.md,contract.json,evidence.json}` (v3: 69 anchors + 34 `derived.policyRegistry` entries) and `../desktop-coverage-closure/round4/final-review/GF-final.{md,json}`. The 34-key registry is generated into [policy-registry.ts](policy-registry.ts) from `evidence.json`, never hand-copied. The raw fragments, UTF-16 offsets and chunk hashes of the two monitoring-notice helpers (`LD`, `Aje`) are recorded in `final-core-fixes-evidence.json`, added in the same directory (the original evidence is unchanged). The quota consumer-unit facts come from `R/phase35/completion-evidence/{quota,CONTRACT.md}` and `followup/CONTRACT.md`: the top-level window `utilization` is consumed as a percentage, `limits.percent` documents 0–100, and `resets_at` documents ISO; **the declarations read contain no min/max or datetime validation**, so finite/range/ISO are supplied by this module's application validation, without claiming a server-enforced range or every wire guarantee.

## Ownership boundaries

| Responsibility | Owner |
|---|---|
| Endpoint construction, base URL, egress proxy selection | The caller (this core receives `url`) |
| Credential selection, refresh, CAS commit | The caller's credential owner (this core receives `accessToken` and calls an injected `reauthorize` at most once) |
| Scheduling, polling, recovery beyond the retry budget | The caller (this core returns `recoveryOwner: 'caller'`) |
| How a verdict restricts a concrete operation, whether a tool runs | The caller (this core returns only `allow`/`deny`/`unsupported` with a fixed reason) |
| Remote flags, taint sources, HIPAA evidence | Injected by the caller (this core does not read GrowthBook and takes no production value) |

## Exported API

- `parsePolicyLimitsDocument(raw)` → `{ ok, document } | { ok:false, failure }`: canonicalizes against the fixed envelope; `restrictions` (and its `allowed`) is required, and the taints are normalized (lowercase/trim, `^[a-z0-9_-]{1,64}$`, deduplicated, ≤16), as are the monitoring notice, `defaults` and `core_skills` (≤256×128); unknown keys are stripped.
- monitoring notice: `text` is first measured as `≤500` by its original value, then normalized by `LD(text,'',{keepEmojiJoiners:true})` (a lone surrogate → U+200B, ANSI escapes removed, control/format/private-use/unassigned/ignorable classes and `U+2028/U+2029/U+2800` deleted, ZWJ/VS15/VS16 kept, and only a joiner run at the start of the text or after whitespace removed); `url` passes the https/`URL()` check and then `Aje` (any of a control, `Cf`, `Default_Ignorable_Code_Point`, `U+2028/U+2029/U+2800`, a lone surrogate or `U+10EEEE` makes it invalid), and an invalid one drops only the url and keeps `{text,url:null}`.
- `policyValidator(raw)` / `canonicalPolicyJson(value)` / `sha256Hex(text)`: computes `sha256:<hex>` over the canonical JSON of the **raw body** (object keys sorted recursively; WebCrypto preferred, Node crypto as fallback).
- `PolicyLimitsCache`: a single-snapshot in-memory adoption cache (`adopt/current/live/validator/clear`) whose signature is kept for diagnostics only, takes no part in adoption and is never persisted.
- `evaluateLivePolicy(key, document, taints, inputs?)`: the `Fzt` order (hardBlockUnder → explicit `allowed` → transcript scan → merge taint); the transcript-scan step applies only when `inputs` is passed and `transcriptScan && !transcriptScanIgnoresRegistry` holds, and omitting it keeps the old "answer after taint" behavior; an unregistered key → `unsupported`.
- `evaluateWithoutLivePolicy(key, inputs)` / `policyDenyKind` / `latchedDeny` / `isPolicySettled`: `sn`/`Ch`/`pwn`/`O4r`, with every input injected (see `PolicyVerdictInputs`).
- `readPolicyLimits(operation)`: a bounded GET (role headers + Bearer + conditional `If-None-Match`), status classification, `Retry-After`, a 5-attempt retry budget and cancellation; version/permission refusals are decided by the injected `classifyFailure` and stay terminal (**before** the 401 replay).
  - `priorContext: 'live' | 'stale' | 'none'` (`PolicyPriorContext`, the same three states as the consumer's `PolicyLimitsStatus.fallback`): the default infers "validator present ⇒ `live`, otherwise `none`" and never infers `stale`.
  - `failOpenOnMissingRoute` (the caller's `!rustlingOrbit`) returns `fail_open_empty` only when `priorContext === 'none'`, for a `404` or an unconditional `304` (`route_missing_fail_open` / `unsolicited_304_fail_open`); `live`/`stale` always return `failure`, the caller keeps its own cache and stale document, and this core neither reads nor clears it. A `304` is a revalidation only when it is `live` and really carries a validator.
- `parseOrgPin(value)` / `validateOrgPin(request)`: the pin is a string or a non-empty string[]; **a bodyless `POST /api/oauth/validate` is sent only when a pin is present** (Bearer + UA + JSON content-type, 10s); a missing result is refused as `org_verify_failed`, a mismatch as `org_pin_mismatch` and an empty set as `invalid_input`.
- `parseRawFacts(get)`: **one** read of the entire `anthropic-ratelimit-unified-*` family (member names and window names are exported by this module, and the plugin wrapper's family gate reuses the same vocabulary), recording `presence` (`absent` / `present` / `present-zero` / `invalid`) and `parsedNumber` per member. Both a missing and a blank value read as `absent`, and `Number('')`/`NaN`/`Infinity` **must not become 0**; text that is present but not a finite number ⇒ `invalid` with no `parsedNumber` (the presence of `parsedNumber` is the only validity criterion). A source without a `get` method throws (an internal invariant, not wire tolerance).
- `projectLegacy(facts, { resolveReset, now })`: produces a report with exactly the same per-field shape as the plugin's existing `UnifiedRateLimitState`; the reset is resolved by the injected port, the core does not copy that algorithm, and `observedAt` takes the injected `now`.
- `projectStrict(facts, { now })`: produces `ClaudeQuotaObservation[]` only when a member is a finite number; header `utilization` is a 0–1 ratio, converted **only once** into `normalizedPct` while keeping `unit: 'ratio'`. A header reset is recognized only in **the epoch-seconds interval this application selects**: a pure decimal non-negative integer that is ≤ `CLAUDE_QUOTA_MAX_EPOCH_SECONDS` (`253402300799` = `9999-12-31T23:59:59Z`, the last second of a four-digit RFC3339 year; not deployment-tunable and not a server limit) is converted to milliseconds; everything else (decimals, exponents, durations, HTTP-dates, out-of-range values, 13-digit millisecond magnitudes) is `resetFormat: 'unknown'` with no instant and is **not automatically reinterpreted as milliseconds**. Missing/invalid values are **not clamped to 0 or 100**.
- `parseRawFacts` reads by member type: token fields (`status`/`overage-status`/`representative-claim`/`fallback`/`overage-disabled-reason`/`overage-in-use`/`overage-scope`) and reset fields are `text`/`reset`, and present text means `presence:'present'` with `rawText` retained — an unknown token is read as `other` by the status projector, and a valid HTTP-date/duration reset stays parseable on the legacy side as before; only a `numeric` field (`*-utilization`, `*-surpassed-threshold`) whose text is not a finite number is `invalid`. **`Number` must not be applied generically to the whole family**.
- `parseUsageJson(body, now, options?)`: a non-empty `limits` takes precedence over the flat top-level keys. **The three window states are kept separate**: a missing key or an explicit `null` = **not observed** (no code counted, no row produced, no fabricated 0); an object at the key whose `utilization` is missing/non-finite (including `{}`) = **an unreadable window**, counting one `percent-missing` and producing no row; a finite number at the key = the window exists and is projected by the two rules below. **The application's percent-range check decides only whether strict is known**: finite but out of range ⇒ **the legacy window keeps its original value as before** (the old `claudeLimitsWindows` required only a finite number), and with `wantsStrict` it produces no observation and counts one `percent-out-of-range`; `?? 0` is forbidden. The above holds with **the same semantics** in both the flat and the `limits` branches (a `limits` row uses the presence/usability of percent as the same criterion).
- The two readings of `resets_at` come from **the same read**: on the legacy side any string `Date.parse` can parse yields an instant (HTTP-dates, `01/02/2026`, and invalid calendar ISO normalized by the runtime all stay as before), while the strict side recognizes only the **RFC3339 subset** this module verifies (`YYYY-MM-DDThh:mm:ss[.fff]` with a mandatory `Z` or `±HH:MM`, plus a real calendar check, so `2026-02-30` and `02-29` in a non-leap year both fail) — a non-conforming string keeps `resetFormat:'unknown'` with no instant and **does not narrow legacy because of it**. A number never counts as an instant (the model row's numeric-seconds branch is not generalized). **Undeclared (a missing key or an explicit `null`) is missing information, not a bad value**: it counts no `reset-shape-invalid` and fabricates no date/0; an explicit `0` is a value (epoch second 0 = `1970-01-01T00:00:00Z`, whose staleness the caller's freshness still decides) and is distinguishable from missing.
- The closed `kind` enum `5h | 7d | 7d_oi | overage | unknown` is **the enum of header-family tokens** (`7d_oi`/`overage` come only from header windows); the usage JSON side produces only `5h`, `7d` and `unknown` for an unrecognized `limits` kind. `scopeKind` is the "who is covered" dimension (see above). Unrecognized top-level keys are counted only in `unknownTopLevelKeys` (**no separate issue code and no key name echoed back**), and `display_name` enters no observation or error text. Each code in `issues` is counted once and never duplicated: `window-shape-invalid`, `percent-missing`, `percent-out-of-range`, `reset-shape-invalid`, `limit-kind-unknown`, `window-key-unsupported`.

## Configuration behavior statement

The compile-time defaults `parseFailureIsTerminal=false` and `refuseFailOpenOnMissingRoute=false` (`DEFAULT_POLICY_VERDICT_INPUTS`) mean: a parse failure is retryable, and a 404/304 with no cache fails open to an empty policy. This is **this module's configuration behavior** and does not claim to equal the deployed values; the deployed values are injected by the caller.

## Product-guard statements (deliberate differences)

`POLICY_LIMITS_BODY_LIMIT` (65536) and `ORG_PIN_BODY_LIMIT` (8192) are this module's **own** body byte bounds, not fixed source constants of the analysed client: its response-body reads have no such constant. Exceeding a bound is terminal — a policy read becomes `unsupported/body_over_limit` (`skipRetry:true`, spending no further retry budget on the same large document) and an org pin becomes `org_verify_failed/body_over_limit`; in both cases the body content reaches no failure, log or cause.

The ANSI removal inside `LD` corresponds to the runtime's `Bun.stripANSI` (a native builtin, whose source is not in the fixed raw): this module removes whole escape sequences — CSI/SGR, OSC/DCS and the like — rather than deleting only the ESC and leaving a printable tail. **This step does not claim to be fully equivalent to `Bun.stripANSI`** — behavioral differences outside escape sequences are unclosed, and byte-for-byte alignment first requires the source of that builtin. The raw fragments and their sources are recorded in `R/phase34/business-followup/policy-limits-implementation/final-core-fixes-evidence.json`.

The analogous deliberate preservations and known limitations on the quota side:

- **The legacy label keeps its original compatible behavior and gains no bound**: a `limits` row's `display_name` enters the legacy `windows[].scope` exactly as the response carries it, and this module does **not** strip control characters or limit the character set or length. The existing UI emits that value directly as copy (escaped by React, not an injection surface) and it takes part in the existing `w.scope === model` matching semantics; narrowing it would change verified UI behavior and model matching without authorization, so **the legacy label is not claimed to be bounded**.
- **`seven_day_oauth_apps` and `cinder_cove` are recognized but produce no window**: their applicable scope, period and channel are unevidenced, so inventing a unit or emitting an observation as `account` would exceed the evidence. When they appear in the body they count one `window-key-unsupported` and are counted in `rejectedWindowKeys`, and the legacy window list ignores them as the old `claudeLegacyWindow` did.
- **`unknownTopLevelKeys` and `issues` are two separate aggregates**: the former counts only unrecognized top-level keys, and the facts in it do not enter `issues`; the two must not be added together.
- **Strict's ISO reading is a subset this application selects, not a server guarantee**: the accepted shape is `YYYY-MM-DDThh:mm:ss[.fff]` with a mandatory timezone (`Z`/`±HH:MM`) passing a real calendar check; the source client declares only "ISO 8601" for `resets_at` and validates no content, so **it is not claimed that the CC server emits only that shape**, nor that invalid calendar values do not exist server-side — this application simply produces no known instant from them.
- **Two unknowns left in place (they do not affect the finite implementation above)**: a payload row → a stable model identity (`scope.model.display_name` is only a display name, and membership in `Fft`/`Hre`'s lists does not constitute a row binding), and the exact server-side grouping of `7d_oi`. Neither is filled in by guessing: this module outputs only `unknown-scope` and the proven family, inventing no ID and merging no window.
- **A consumer that projects only account windows**: `model-family`, `7d_oi`, `overage` and `weekly_scoped` — everything beyond `5h`/`7d` (the corresponding keys in the header and in the usage JSON) — are **retained internally and withheld as needed**; a scope must not be deleted and forced into weekly because the carrier cannot hold it, nor may a missing field be used to mean it is account.
